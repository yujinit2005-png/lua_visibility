# [LUVIS] 병원정보 질문관리 확장 및 차세대 AI 가시성 평가 엔진 v1.0 종합 설계서

---

## 1. 프로젝트 개요 및 배경

### 1.1 배경 및 목적
본 문서는 `mdFile/0. 병원검색 키워드 조정 및 평가기준 수립.md`의 표준 방법론과 기존 LUVIS Web 시스템 분석을 바탕으로 수립되었습니다.
기존 단순 텍스트 나열형 키워드 관리 및 단일 점수 산정 방식에서 벗어나, **매월 동일한 질문으로 AI 검색 점유율과 신뢰도를 측정할 수 있는 표준 패널 시스템(v1.0)**을 구축하는 것을 목적으로 합니다.

### 1.2 핵심 설계 요구사항
1. **병원정보관리 내 질문 항목 확장**: 질문 버전, 질문 코드, 질문 문구, 관리 분야(5대 Intent), 평가 기준(AEO/GEO/Trust 루브릭) 관리.
2. **API vs 크롤링(Web UI) 교차 비교 분석**: 동일 질문에 대해 AI API 응답과 실제 웹 챗봇 크롤링 결과를 비교·검증하여 데이터 신뢰도 확보.
3. **리포트 구조의 명확한 분리**:
   - **1~4페이지 (질문 기반 AI 응답 분석)**: AI 가시성, AEO 지표, 질문별 Opportunity Map, Competitive Matrix
   - **5~7페이지 (홈페이지 웹 자산 감사)**: GEO 준비도(크롤러, 스키마, 기술가독성), Trust Signal 자산(의료진, FAQ, 칼럼, YouTube), Action Priority
4. **엔진 버전 분리 및 Dual Run 아키텍처**:
   - 기존 분석 로직을 **Engine v0.9**로 고정(Fix)
   - 신규 4대 지표(100점 만점) 및 체크리스트 기반 분석 로직을 **Engine v1.0**으로 독립 구현
   - 1회 수집된 원천 데이터를 활용하여 **두 개 엔진(0.9 vs 1.0)을 동시 실행(Dual Run)**하고 비교 리포팅하는 파이프라인 구축.

## 2. 병원정보 질문 관리 체계 확장 설계

### 2.1 관리 필드 정의
질문은 월별 변동 없는 정량 측정을 위해 구조화된 메타데이터로 관리됩니다.

| 항목명 | 필드명 | 데이터 타입 | 설명 | 예시 |
| :--- | :--- | :--- | :--- | :--- |
| **질문 버전** | `question_version` | `VARCHAR(20)` | Query Set의 버전 식별자 (고정 측정 패널 기준) | `v1.0`, `v0.9` |
| **질문 코드** | `question_code` | `VARCHAR(10)` | 질문의 고유 식별 코드 (월별 추이 추적 키) | `Q01`, `Q02`, ... `Q30` |
| **질문 문구** | `question_text` | `TEXT` | 환자/보호자 관점의 실제 질의 문장 | `용인 처인구에서 혈액투석 받을 수 있는 병원 추천해주세요.` |
| **관리 분야** | `category` | `VARCHAR(50)` | 5대 핵심 의도(Intent) 분류 | `Discovery`, `Expertise`, `Patient Scenario`, `Accessibility`, `Recommendation` |
| **평가 영역** | `eval_area` | `VARCHAR(50)` | 중점 평가 영역 | `AEO`, `GEO`, `Trust`, `AEO/GEO`, `AEO/Trust` |
| **평가 기준 (루브릭)** | `eval_criteria` | `JSONB` | 객관식 체크리스트 및 가중치 정의 | `{"mention": 1, "direct_answer": 1, "doctor_verified": 1, ...}` |

---

### 2.2 30개 고정 질문 세트 (v1.0) 5대 관리분야 분류

```text
[ 30 Fixed Query Panel v1.0 ]
 ├── ① Discovery (발견: Q01~Q05) ──────> 지역 검색 노출 및 인공신장실 시설 탐색 (GEO)
 ├── ② Expertise (전문성: Q06~Q10) ────> 신장내과 전문의, 적정성 평가 등 근거 탐색 (AEO+Trust)
 ├── ③ Patient Scenario (상황: Q11~Q19) ─> 신규환자, 보호자, 고령환자, 복합질환 맞춤 추천 (AEO/Trust)
 ├── ④ Accessibility (접근성: Q20~Q25) ─> 야간투석, 주말투석, 주차, 위치 정확도 (GEO+AEO)
 └── ⑤ Recommendation (추천: Q26~Q30) ──> AI 최종 추천율 및 경쟁병원 대비 Share of Voice (AEO/Trust)
```

### 2.3 병원 성격 및 키워드 기반 맞춤형 30개 질문 자동 생성 엔진 (Query Generator)

각 병원마다 진료과(한방병원, 정형외과, 산부인과, 안과, 신장내과 등)와 주력 치료가 완전히 다르므로, **병원 메타데이터를 기반으로 5대 Intent 30개 고정 질문 세트를 원클릭으로 자동 구성하는 템플릿 룰 엔진**을 구축합니다.

#### 1) 자동 생성을 위한 병원 입력 파라미터
- **병원명 / 대표 별칭 (`aliases`)**: 예) `루아한방병원`, `루아한의원`
- **대표 지역 키워드 (`region_terms`)**: 광역(`용인시`), 기초(`처인구`), 세부 행정동(`김량장동`), 역세권(`김량장역`)
- **병원 성격 / 진료과목 (`specialties`)**: 예) `한방병원`, `정형외과`, `산부인과`, `신장내과`
- **병원 주요 키워드 / 특화 치료 (`main_keywords`)**:
  - *한방병원*: `교통사고입원`, `추나요법`, `도수치료`, `디스크비수술`, `어혈한약`
  - *정형외과*: `무릎인공관절`, `어깨회전근개`, `척추관협착증`, `체외충격파`
  - *산부인과*: `난임치료`, `시험관아기`, `인공수정`, `여성종합검진`, `자궁근종`
  - *신장내과*: `혈액투석`, `인공신장실`, `만성콩팥병`, `신부전`, `야간투석`

#### 2) 5대 Intent별 30개 질문 자동 생성 템플릿 규칙

```text
┌────────────────────────────────────────────────────────────────────────┐
│                   30 FIXED QUERY GENERATION RULES                      │
├───────────────────┬────────────────────────────────────────────────────┤
│ ① Discovery       │ • Q01: [기초지역]에서 [대표진료/특화치료] 받을 수 있는 병원 추천  │
│    (Q01~Q05)      │ • Q02: [기초지역]에 [대표시설/입원실]이 있는 병원 어디인가요?   │
│                   │ • Q03: [세부동] 근처에서 [대표진료] 잘하는 병원 어디인가요?      │
│                   │ • Q04: [역세권] 근처에서 다니기 편한 [병원성격] 추천해주세요    │
│                   │ • Q05: [기초지역]에서 [진료과1]과 [진료과2/특화치료] 함께 하는곳   │
├───────────────────┼────────────────────────────────────────────────────┤
│ ② Expertise       │ • Q06: [광역지역]에서 [전문의자격]이 진료하는 [병원성격] 추천    │
│    (Q06~Q10)      │ • Q07: [광역지역]에서 [대표질환]을 전문적으로 치료하는 곳 어디?   │
│                   │ • Q08: [광역지역]에서 [만성질환/장기치료] 환자가 믿고 다닐 병원 │
│                   │ • Q09: [광역지역]에서 [특화치료] 환자를 체계적으로 관리하는 병원 │
│                   │ • Q10: [광역지역]에서 [의료평가/임상경험]이 우수한 병원 추천     │
├───────────────────┼────────────────────────────────────────────────────┤
│ ③ Patient Scenario│ • Q11: [광역지역]에서 [대표치료]를 잘하는 병원은 어디인가요?     │
│    (Q11~Q19)      │ • Q12: [기초지역]에서 [병원성격]을 고른다면 어떤 병원 추천?     │
│                   │ • Q13: [대표질환/수술]을 처음 고민하는데 어디로 가야 하나요?     │
│                   │ • Q14: 부모님이 [대표질환] 치료를 받으셔야 하는데 추천 병원?   │
│                   │ • Q15: [광역지역]에서 고령 환자가 편하게 다닐 수 있는 병원?     │
│                   │ • Q16: [주요질환1]과 [동반질환2]를 함께 치료할 수 있는 병원?     │
```

## 3. API 결과 vs 크롤링(Web UI) 결과 교차 비교 분석 엔진

### 3.1 교차 분석 목적 및 구조
- **API 응답**: 시스템이 LLM API(OpenAI, Gemini, Perplexity 등)를 통해 직접 수집한 정형 텍스트.
- **크롤링(Web) 응답**: 실제 브라우저 챗봇 세션에서 일반 사용자 인터페이스를 통해 수집한 텍스트.
- **교차 분석 메커니즘**:
  1. **일치율(Consistency Rate)**: API와 Web 응답 간의 병원 언급/추천 일치 여부 판정
  2. **환각 및 괴리 탐지**: API에서는 추천되나 Web에서는 배제되는 현상 또는 그 반대 현상 감지
  3. **신뢰도 지수 산출**: 질의당 측정 안정성 지수(Confidence Level) 반영

```text
[ 질문 세트 (Q01 ~ Q30) ]
        │
   ┌────┴──────────────────────────┐
   ▼                               ▼
[ AI API 호출 엔진 ]        [ 웹 크롤러 에이전트 ]
   │ (OpenAI, Gemini, etc.)        │ (Playwright/Selenium Web UI)
   ▼                               ▼
[ API Raw Answers ]         [ Web Raw Answers ]
   └───────────────┬───────────────┘
                   ▼
       [ 교차 비교 분석기 (Cross Analyzer) ]
       ├─ 언급 일치 여부 (Mention Match)
       ├─ 추천 일치 여부 (Recommendation Match)
       ├─ 순위 변동 (Position Delta)
       └─ 괴리 원인 분류 (검색 그라운딩 차이, 실시간 웹 검색 등)
```

- **컨설팅 연계 진단**: 단순 점수가 아닌 제작 및 확충이 필요한 자산 목록 명시

  4. robots.txt AI 크롤러 수집 통로 허용
  5. 주요 환자 질문 키워드 기반 홈페이지 웹 자산 최적화

   - **AEO 질문형 콘텐츠 자산화**: 30개 고정 질문 및 대표 질환별 심층 Q&A, 원장 칼럼 텍스트를 발행하여 AI의 직접 답변 후보로 선점
   - **Trust 미디어 자산 강화**: 전문의 질환 해설 YouTube 영상 제작 및 홈페이지 양방향 연결로 AI의 멀티모달 신뢰도 극대화
3. **어떻게 성과를 증명하는가? (3단계 증명 체계)**
   - **동일 30개 패널 월간 추적**: 측정 기준을 고정한 상태에서 전월 대비 점수 증감(+점, +%p)과 랭킹 개선을 숫자로 입증
   - **경쟁병원 점유율 역전 증명**: "경쟁사 점유율 45% vs 당사 18%" 상태에서 당사 점유율이 35% 이상으로 역전되는 과정을 매트릭스로 가시화
   - **AI 답변 원문 아카이빙 비교**: "과거: 단순 나열" → "현재: 전문의 및 인공신장실 근거와 함께 1순위 추천"으로 변화된 실제 AI 문장을 제시하여 마케팅 성과를 명확히 입증

#### [11p] Glossary: AI 가시성 & 마케팅 표준 용어 사전
병원 경영진과 마케팅 실무자가 리포트의 비즈니스 가치를 쉽게 이해할 수 있도록 용어의 정의와 마케팅적 의미를 명확히 정리합니다.

| 전문 용어 | 영문 표기 | 마케팅 및 비즈니스 관점의 정의 |
| :--- | :--- | :--- |
| **루비스 AI 스코어** | LUVIS Score | AI 검색 환경에서 우리 병원이 환자에게 발견되고 추천될 확률을 정량화한 종합 경쟁력 지수 (100점 만점) |
| **AEO** | Answer Engine Optimization | 검색창 링크 클릭을 유도하는 기존 SEO를 넘어, AI의 생성형 답변 문장 자체에 우리 병원이 정답으로 추천되도록 최적화하는 전략 |
| **GEO** | Generative Engine Optimization | 생성형 AI 크롤러가 병원 웹사이트의 구조와 진료 정보를 왜곡 없이 빠르고 정확하게 이해할 수 있도록 웹 자산을 기술적으로 최적화하는 영역 |
| **Trust Signal** | Trust Signal Assets | AI가 병원을 환자에게 추천할 때 '신뢰할 만한 근거'로 채택하는 의료진 이력, FAQ, 심평원 평가, 전문 칼럼, YouTube 영상 등의 검증 가능한 디지털 자산 |
| **Share of Voice (SOV)** | AI Share of Voice | 특정 지역/진료과 질의에서 AI가 언급한 전체 병원 중 당사 병원이 차지하는 시장 내 AI 노출 점유율(%) |
| **30 Fixed Query Panel** | 30 Fixed Query Panel | 월별 마케팅 성과와 점수 변동의 인과관계를 왜곡 없이 과학적으로 비교·증명하기 위해 고정 설계된 30개의 표준 환자 질의 세트 |
| **교차 검증** | Cross-Verification | AI API 응답과 실제 웹 챗봇 검색 응답을 비교하여, AI 환각(Hallucination)을 배제하고 실제 환자가 마주하는 답변의 일관성을 검증하는 기술 |
| **구조화 데이터** | Schema.org JSON-LD | AI 기계가 읽을 수 있도록 병원명, 진료과목, 전문의, 진료시간 등을 표준 메타데이터 규격 코드로 웹사이트에 심는 작업 |
| **Opportunity Map** | Opportunity Map | 전체 환자 질문을 선점기회(Blue Ocean), 탈환대상(경쟁사 우세), 유지영역(자사 우세), 경합영역으로 분류하여 마케팅 집중 순위를 정하는 전략 지도 |

## 5. 다중 분석 엔진(v0.9 vs v1.0) 및 소스 파일 물리적 분리 아키텍처

### 5.1 소스 파일 및 디렉토리 분리 구조 (Strategy Pattern)
3, 4, 5단계 핵심 로직은 단일 파일 내부의 분기문이 아니라, **폴더/파일 단위로 물리적으로 완전 분리**하여 개발 및 관리합니다.

```text
src/lib/
 ├── engine/
 │    ├── types.ts                     # 공통 데이터 인터페이스 (RunOptions, Answer, RawData 등)
 │    ├── engineDispatcher.ts          # [오케스트레이터] 1~2단계 공통 수집 후 0.9 / 1.0 / Dual 분기 실행
 │    ├── crossAnalyzer.ts             # [공통] API 결과 vs 웹 크롤링 결과 교차 비교 분석 모듈
 │    │
 │    ├── v09/                         # 🔒 [Engine v0.9 독립 파일군 - 테스트 기준선/고정]
 │    │    ├── analyzerV09.ts          # (3단계) v0.9 가시성/언급/추천 분석 로직
 │    │    ├── trustSignalV09.ts       # (4단계) v0.9 레거시 GEO/Trust 단일 합산 로직
 │    │    └── reportGeneratorV09.ts   # (5단계) v0.9 기존 9p 통합 PDF/HTML 생성기
 │    │
 │    └── v10/                         # ✨ [Engine v1.0 독립 파일군 - 정밀 평가/확장]
 │         ├── analyzerV10.ts          # (3단계) v1.0 5대 카테고리 루브릭 평가 및 Visibility/AEO 산정
 │         ├── trustSignalV10.ts       # (4단계) v1.0 GEO(25점) vs Trust Signal(25점) 완전 분리 감사
 │         └── reportGeneratorV10.ts   # (5단계) v1.0 11p 확장형 신규 리포트 생성기
 │
 ├── analyzer.ts                       # 기존 진입점 (engineDispatcher와 연동하여 하위 호환 유지)
 └── reportGenerator.ts                # 기존 진입점 (버전에 따라 v09/v10 리포트 자동 라우팅)
```

### 5.2 진단 실행 5단계 프로세스 상세 설계

수집 단계(2단계)까지는 **공통 원천 데이터(Raw Data)**를 1회만 수집하고, 이후 3~5단계는 **선택된 엔진 버전(v0.9 / v1.0 / Dual)**에 따라 독립적으로 분기 실행됩니다.

```mermaid
flowchart TD
    S1[1단계: 진단 설정 로드\n(병원/질문버전/엔진선택)] --> S2[2단계: 데이터 수집\n(AI API 호출 + 홈페이지 크롤링)]
    
    S2 --> ModeCheck{엔진 실행 모드}
    
    ModeCheck -->|v0.9 단독| E09[3~5단계: Engine v0.9 실행\n(레거시 스코어링 & 0.9 리포트)]
    ModeCheck -->|v1.0 단독| E10[3~5단계: Engine v1.0 실행\n(4대 지표 스코어링 & 1.0 리포트)]
    ModeCheck -->|Dual Run 동시| EDual[3~5단계: Dual Run 병렬 실행\n(v0.9 & v1.0 동시 평가 + A/B 비교)]
    
    E09 --> SaveDB[결과 DB 저장 & 리포트 생성]
    E10 --> SaveDB
    EDual --> SaveDB
```

#### 단계별 상세 처리 로직

1. **1단계: 진단 대상 및 설정 로드 (`init`)**
   - 대상 병원 정보(`hospitals`), 질문 세트(`hospital_questions` / `hospital_config_versions`), 활성화된 AI 모델, API 키 로드.
   - 실행 모드 설정: `engine_version` = `0.9` | `1.0` | `dual`

2. **2단계: 원천 데이터 수집 (`measurement`)**
   - **AI 질의 수집**: 선택된 AI 도구(OpenAI, Gemini, Perplexity, Naver, Claude)에 질문(Q01~Q30) 질의 후 `answers`에 Raw 응답 저장.
   - **홈페이지 크롤링**: 병원 홈페이지 HTML, `robots.txt`, 메타데이터 수집.
   - **웹 크롤러 에이전트 연동 (선택)**: 로컬 크롤러를 통해 웹 UI 챗봇 답변 수집 (`web_verification_answers`).

3. **3단계: 가시성 / AEO / 질문 분석 (`scoring`)**
   - **Engine v0.9**: 정규식 및 별칭 매칭 기반 언급/추천 여부 산정.
   - **Engine v1.0**: 5대 카테고리별 세부 체크리스트(루브릭) 적용, API vs Web 교차 검증, 4대 지표(Visibility, AEO) 정밀 점수화.
   - **Dual Mode**: 동일한 Raw Answers에 대해 0.9 파서와 1.0 파서를 각각 순차 실행하여 결과를 각각 생성.

4. **4단계: GEO 준비도 & Trust Signal 분석 (`trust`)**
   - **Engine v0.9**: 기존 단일 합산 방식(GEO Readiness = Trust Signal 52점).
   - **Engine v1.0**:
     - GEO 엔진: 크롤러(25) + 스키마(30) + 기술요소(20) = 75점 만점 환산 (검색엔진 접근성)
     - Trust 엔진: 의료진(7) + FAQ(6) + 칼럼(6) + YouTube(6) = 25점 만점 환산 (신뢰 증거 자산)
     - 명확히 분리된 점수 체계 산출.

5. **5단계: 리포트 생성 및 PDF 렌더링 (`render`)**
   - **Engine v0.9**: 기존 9p 템플릿 생성.
   - **Engine v1.0**: 11p 확장 표준 템플릿 렌더링 및 Supabase Storage 업로드.
   - **Dual Mode**: v0.9 리포트와 v1.0 리포트를 모두 생성하고, 두 엔진 간 점수 차이를 보여주는 `A/B Comparison View` 제공.

## 6. 데이터베이스(Supabase) 스키마 변경 설계

### 6.1 신규 테이블: `hospital_questions` (질문 마스터)
기존의 `hospital_config_versions.queries` 단순 텍스트 컬럼을 대체·확장하는 정규화 테이블입니다.

```sql
CREATE TABLE IF NOT EXISTS public.hospital_questions (
    id bigint PRIMARY KEY GENERATED BY DEFAULT AS IDENTITY,
    hospital_code text NOT NULL REFERENCES public.hospitals(hospital_code) ON DELETE CASCADE,
    version text NOT NULL DEFAULT 'v1.0',
    question_code text NOT NULL, -- e.g. 'Q01', 'Q02' ~ 'Q30'
    question_text text NOT NULL,
    category text NOT NULL,      -- 'Discovery', 'Expertise', 'Patient Scenario', 'Accessibility', 'Recommendation'
    eval_area text NOT NULL,     -- 'AEO', 'GEO', 'Trust', 'AEO/GEO', 'AEO/Trust'
    eval_criteria jsonb DEFAULT '{}'::jsonb, -- 세부 체크리스트 루브릭
    sort_order integer DEFAULT 0,
    is_active boolean DEFAULT true,
    created_at timestamp with time zone DEFAULT now(),
    updated_at timestamp with time zone DEFAULT now(),
    UNIQUE(hospital_code, version, question_code)
);

CREATE INDEX idx_hospital_questions_lookup ON public.hospital_questions(hospital_code, version);
```

### 6.2 테이블 확장: `hospitals` & `hospital_config_versions`
병원 성격(진료과목) 및 특화치료/주요키워드를 저장하기 위한 컬럼 추가.

```sql
-- hospitals 마스터 테이블 확장
ALTER TABLE public.hospitals 
ADD COLUMN IF NOT EXISTS specialties text,       -- e.g. '한방병원', '정형외과', '산부인과', '신장내과'
ADD COLUMN IF NOT EXISTS main_keywords text;     -- e.g. '교통사고입원, 추나요법, 도수치료' (줄바꿈/콤마 구분)

-- hospital_config_versions 버전 테이블 확장
ALTER TABLE public.hospital_config_versions
ADD COLUMN IF NOT EXISTS specialties text,
ADD COLUMN IF NOT EXISTS main_keywords text;
```

### 6.3 테이블 확장: `runs`
엔진 버전 관리 및 다중 엔진 실행 결과를 보관하기 위한 컬럼 추가.

```sql
ALTER TABLE public.runs 
ADD COLUMN IF NOT EXISTS engine_version text DEFAULT '0.9',
ADD COLUMN IF NOT EXISTS dual_run boolean DEFAULT false,
ADD COLUMN IF NOT EXISTS v1_visibility_score double precision,
ADD COLUMN IF NOT EXISTS v1_aeo_score double precision,
ADD COLUMN IF NOT EXISTS v1_geo_score double precision,
ADD COLUMN IF NOT EXISTS v1_trust_score double precision,
ADD COLUMN IF NOT EXISTS v1_total_score double precision,
ADD COLUMN IF NOT EXISTS v1_evaluation_details jsonb,
ADD COLUMN IF NOT EXISTS cross_analysis_summary jsonb;
```

### 6.4 테이블 확장: `answers`
질문 코드 및 세부 평가 체크리스트 결과 보관을 위한 컬럼 추가.

```sql
ALTER TABLE public.answers 
ADD COLUMN IF NOT EXISTS question_code text,
ADD COLUMN IF NOT EXISTS category text,
ADD COLUMN IF NOT EXISTS rubric_score jsonb, -- e.g. {"direct_answer": 5, "accuracy": 5, "completeness": 5}
ADD COLUMN IF NOT EXISTS cross_verified boolean DEFAULT false,
ADD COLUMN IF NOT EXISTS engine_version text DEFAULT '0.9';
```
